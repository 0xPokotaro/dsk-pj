## DG SPS 概要

- ステーブルコイン決済事業に注力しており、対面/非対面/Agent決済のいずれにも適用可能なプロダクトを提供。
- 既存サービスを大きく改修することなく、**API連携**でステーブルコイン決済を導入可能(ブロックチェーン特有の仕様を意識する必要なし)。
- マルチチェーン・マルチ銘柄に一括対応(個別チェーン/ウォレットごとの開発対応は不要)。
- 人間の決済に加え、AI Agentによる自律決済(HTTP 402ベース／x402プロトコル)にも対応。
- 日本円での売上金精算に対応(ステーブルコインでの精算も検討可能)。

### 対応アセット / チェーン

| 対応アセット | 対応チェーン |
|---|---|
| JPYC、USDC | Polygon、Ethereum、Base |

※ 各アセットは対応するチェーン上でのみ利用可能。今後、お客様ニーズに応じて順次追加予定。

### ステーブルコイン決済のメリット

| 加盟店メリット | 消費者メリット |
|---|---|
| 安価な決済手数料 | 越境時の安価な為替手数料 |
| 越境でも同一の決済手数料(国境のないブロックチェーン基盤) | 他国通貨建てSC決済時の為替手数料がカード決済より安価 |
| チャージバックが存在しない(ブロックチェーン上で確定した取引は第三者により強制取消不可) | |

## 連携の全体像(利用イメージ)

DG提供資料(p.9)より、DG SPSとの連携における登場人物と処理の流れは以下の通り。

```
ユーザー(Human/AI Agent)
   │ 決済(QR/POS/EC)         ▲ 商品/結果
   ▼                          │
  加盟店 ──── 決済処理 ──────▶ 決済事業者(DSK収納代行 想定) ─── 決済処理 ───▶ Stablecoin Payment Service(DG SPS)
         ◀──── 結果通知 ──────                ◀── 結果通知 ──                        │  │
                               │ 精算(日本円)                    ┌───────────────────┘  │
                               ▼                                 │  トランザクション整合性検証(署名妥当性/仕様準拠/二重使用確認)
                                                                  │  アドレススクリーニング(制裁対象アドレス確認)
                                                                  ▼
                                                              Blockchain
                                                          (送金指示 ⇄ 処理結果)
```

- 決済事業者(決済代行/カード会社/金融機関など)を経由せず、**加盟店から直接DG SPSに決済リクエストを投げる形での利用も可能**。
- AI Agentはウォレットから直接SC送金する経路も用意されている(既存のQR/POS/ECチャネルを介さない)。

## アドレススクリーニングの仕組み(p.11)

不正なウォレット(制裁対象国・テロ組織・ハッカー集団関連等)からの決済を未然に防ぐ機能。

1. ユーザーが決済 → ウォレットの過去取引をBlockchainから取得
2. 制裁リストと簡易リスク照合
3. 高単価(目安10万円以上)の場合、外部リスク判定サービスと本格リスク照合
4. リスク判断 → OK/NGを返却

## 接続方法(p.12)

既存サービスを新たに作り変えたり大きく改修することなく導入可能。以下3種類の対応が必要。

| # | 対応内容 | 詳細 |
|---|---|---|
| 1 | 金種追加 | 既存サービス(決済I/F: QR・POS・EC)側に「ステーブルコイン決済」用のチェックアウト項目を追加 |
| 2 | API連携(通常決済) | 「ステーブルコイン決済」選択時の接続先としてDG SPSを指定し決済情報を送信。確定した決済情報を受け取る処理を追加(ウォレット接続 → 支払い通貨・チェーン選択 → トランザクション検証 → 決済確認) |
| 3 | API連携(Agent決済) | x402プロトコルに準拠したフォーマットでDG社Facilitatorを接続先として設定し決済を行う |

DSK収納代行としては、**#2(通常決済)のAPI連携**を用いて「決済事業者」の立ち位置でDG SPSと接続する形が基本形になると想定される(要すり合わせ)。将来的にAgent経由の収納にも対応する場合は#3も検討対象。

## 連携フロー(たたき台 — 要確認)

DG提供資料の「利用イメージ」をベースに、DSK収納代行を「決済事業者」として当てはめた場合のフロー案。詳細は[シーケンス図](diagrams/sequence.html)を参照。

1. ユーザーが加盟店(QR/POS/EC)で決済を実行
2. 加盟店 → DSK収納代行へ決済処理リクエスト
3. DSK収納代行 → DG SPSへAPI連携で決済情報送信(ウォレット接続/通貨・チェーン選択)
4. DG SPS内部でトランザクション整合性検証・アドレススクリーニングを実施
5. DG SPS → Blockchainへ送金指示、処理結果を受領
6. DG SPS → DSK収納代行へ決済結果通知
7. DSK収納代行 → 加盟店へ結果通知、後日(日本円で)精算
8. 加盟店 → ユーザーへ決済完了を通知/商品提供

> **未確認事項**
> - DSK収納代行とDG SPSの契約上の位置付け(直接契約か、DGFT等を介するか)
> - 決済のトリガー起点(ユーザー操作起点か、DSK収納代行のバッチ処理起点か等)
> - 精算のタイミング・サイクル、二重使用や失敗時のエラーハンドリング
> - AI Agent経由の収納(x402)を対象に含めるか
