p.7サービス概要

ステーブルコイン決済事業に注力しており、対面 / 非対面 / Agent決済のいずれにも適用可能なプロダクトを提供。

既存サービスを大きく改修することなく、API連携でステーブルコイン決済を導入可能(ブロックチェーン特有の仕様を意識する必要なし)。マルチチェーン・マルチ銘柄に一括対応し、個別チェーン/ウォレットごとの開発対応は不要。

人間の決済に加え、AI Agentによる自律決済(HTTP 402ベース / x402プロトコル)にも対応。日本円での売上金精算に対応(ステーブルコインでの精算も検討可能)。

p.10対応アセット / チェーン

対応アセット — JPYC、USDC

対応チェーン — Polygon、Ethereum、Base

各アセットは対応するチェーン上でのみ利用可能。今後、顧客ニーズに応じて順次追加予定。

p.8決済によるメリット

加盟店 — 安価な決済手数料 / 越境でも同一の決済手数料(国境のないブロックチェーン基盤) / チャージバックが存在しない(ブロックチェーン上で確定した取引は第三者により強制取消不可)

消費者 — 越境時の安価な為替手数料(他国通貨建てSC決済時の為替手数料がカード決済より安価)

p.11アドレススクリーニング

不正なウォレット(制裁対象国・テロ組織・ハッカー集団関連等)からの決済を未然に防ぐ機能。

  1. ユーザーが決済 → ウォレットの過去取引をBlockchainから取得
  2. 制裁リストと簡易リスク照合
  3. 高単価(目安10万円以上)の場合、外部リスク判定サービスと本格リスク照合
  4. リスク判断 → OK / NGを返却
p.12接続方法

既存サービスを新たに作り変えたり大きく改修することなく導入可能。以下3種類の対応が必要。

  1. 金種追加 — 既存サービス(決済I/F: QR・POS・EC)側に「ステーブルコイン決済」用のチェックアウト項目を追加
  2. API連携(通常決済) — 「ステーブルコイン決済」選択時の接続先としてDG SPSを指定し決済情報を送信。確定した決済情報を受け取る処理を追加(ウォレット接続 → 支払い通貨・チェーン選択 → トランザクション検証 → 決済確認)
  3. API連携(Agent決済) — x402プロトコルに準拠したフォーマットでDG社Facilitatorを接続先として設定し決済を行う
Note DSK収納代行としては、#2(通常決済)のAPI連携を用いて「決済事業者」の立ち位置でDG SPSと接続する形が基本形になると想定される(要すり合わせ)。ただし後続タブのDSK提案資料では、DSKは「決済事業者」ではなく払込票の照会・収納管理を担う立ち位置として整理されている点に注意。

p.2–3サービス全体像

利用者(個人・企業)からDSKが代理受領し、利用者が支払ったSCの種類・各加盟店が受け取りを望むSCの種類に応じて、連携する電取事業者(JPYSC / JPYC・3メガコイン 他)へ振り分けて収納する。

既存収納を希望する加盟店に対しては、DSK信託口座を通じた通常の収納サービスも継続提供する。

他社電取業を活用し、DSKから加盟店へ「日本円→SC」「SC→日本円」「SC→SC」の全パターンに対応する収納サービスを実現する構想。

p.4払込票支払いの追加

DSKが払込票の照会・収納管理機能を提供することで、DG SPSを利用する決済サービスは、既存のステーブルコイン決済フロー(決済処理・トランザクション整合性検証・アドレススクリーニング)を活用しながら、払込票支払い機能を簡単に追加できる。

DG SPS側から見ると「払込票支払機能」は既存の整合性検証・アドレススクリーニングと並ぶ機能ブロックとして追加される位置付け。

p.5連携フロー
  1. DG SPS利用サービスで読み取ったバーコード情報を、DG SPS経由でDSK(収納代行)へ照会
  2. DSKが支払い情報(金額 / 対象加盟店)を返却
  3. DG SPS側で整合性検証・スクリーニングを実施後、SC支払いをDSKへ実行
  4. DSKが結果通知・バーコード情報を受領し、電取業で円転
  5. 加盟店へ入金予定通知 → 日本円送金で精算

ステーブルコイン決済後は、DSKにて決済情報と着金を確認し、加盟店へ日本円を精算する流れを想定している。
